## 2. The five things the revision added on its own

1. **`global/rebuild.lock`.** It is backed and correct. The collapse hunt's M-3 ran the global copy inside one repository's `reindex.lock`, which does not exclude another repository's child. The separate lock with a re-check of the new name under it makes the rename replace nothing (AD-4 L1016–L1027), and the AD-24 case (two rebuilders of one global store started together publish exactly one store) pins it. The residue: its refusal code is undefined (F5-11).
2. **Carrying `whisper_audit`.** It is backed: a correction's attribution goes through `whisper_audit.genre` (AD-5 L1289–L1293), `FR-X6`'s trail cannot be rebuilt, and R4-1 item 5 raised the break. But it is carried with file-id-bearing subject keys, which is **F5-1 (Serious)**.
3. **The purge counting `*.pre-import-*` copies.** It is backed: each kept copy holds rows a replaced store held (M-11), so deleting it unasked would be the loss the refusal prevents. The refusal's advice does not cover what the flag then deletes (F5-7).
4. **L15's two directions and the bound `2^(|ΔrefTs|/h)`.** Correct. Tip up: the fresh cap `min(at, refTs_now)` lies in `(refTs_mined, refTs_now]`, so the factor is at most `2^((refTs_now − refTs_mined)/h)`. Tip down: the fresh cap is `refTs_now`, and the factor is exactly `2^((refTs_mined − refTs_now)/h)`. The direction claims follow from `(P + t)/(C + t)` rising with `t` when `P < C`, and `P/(C + t)` falling with `t`. The collapse hunt's wording (under-confidence on the capped commits only) was indeed wrong. The one wording defect is F5-14 (3).
5. **Keeping `mustExist`.** Backed and correct. With `reindex.lock` never unlinked, a claimant that waited out a purge acquires the same lock. ## 3. Data-safety walk of the rebuild-beside design

For every human-entered row (`corrections`, `human_facts`, `invariants`/`invariant_members`, `human_stated` landmines, global `tuning` owner rows and list keys, global `lessons`, bindings):
- **Normal path.** Rows are copied by column name. File references in `landmines` and `invariant_members` are resolved by path (correct). `corrections.seq` and `whisper_audit.seq` are carried, so the next fold recomputes from watermark 0 and the global replica, which the rebuild does not copy, is republished: consistent. An in-tree-0 `files` row made for a human row is protected from AD-13's unreferenced-row deletion (L2787–L2791): correct. Defects: owner scalar tunings shadowed (F5-2); tuning not validated, and seed changes frozen (F5-3); carried subject keys attached to the wrong files (F5-1); a live session's state dropped (F5-8).
- **Crash at each step.** Steps 1–5 before the rename: only a temporary file exists, the legacy file was only read, and the redo is from scratch (correct, apart from F5-12's stale WAL). Between the rename and step 6: the store exists with no index, and the ordinary staleness spawn finishes it. Duplicate `store_rebuilt` JSONL lines on a redo are harmless. No human row is lost or duplicated on any crash point.
- **Two repositories racing.** Two repositories' children rebuilding the global store are serialised by `global/rebuild.lock`, and the loser is refused and retries on a later event (its code: F5-11). One repository's two children are serialised by `reindex.lock`. No deadlock: every claim has a 100 ms timeout.
- **Purge.** Only `--discard-human` deletes, and only in the project directory, under the reindex lock. Defect: the advice path (F5-7); `global.db` has no deletion path (F5-13).
- **Import.** The pre-import copy keeps every live row. A checksummed export is fine. A legacy export: F5-9.
- **Old build still running.** Nothing is destroyed; later rows are not carried and not reported (F5-18).
- **Verdict on data loss.** No path deletes or overwrites a human-entered row without `--discard-human`, so there is no Critical finding. Two paths make carried owner input wrong in effect (F5-1 on dedup keys, F5-2 on tunings), which is why they are Serious.

## 4. M-18 re-derivation

- `⌈log2 10,000⌉` = 14, so `B = 1,023 − 14 − 1 = 1,008`. `n · 2^B < DBL_MAX` holds with margin (`2^14 · 2^1008 = 2^1022`); the "− 1" is a stated extra margin, and `n · 2^1009` would also be finite. Years: 1,023 × 20 / 365.25 = 56.0; 1,023 × 1.787 / 365.25 = 5.005; 1,008 × 20 / 365.25 = 55.2; 1,008 × 1.787 / 365.25 = 4.93; floor 365.25 × 5 / 1,022 = 1.787. All match the text.
- Tolerance: term `2^−53 · (2 ln 2 · 1,022 + 4)` = 1.577 × 10^−13; sum `(n − 1) · 2^−53` = 1.110 × 10^−12; per sum 1.268 × 10^−12; ratio 2.536 × 10^−12; fresh vs incremental 5.07 × 10^−12; tests at 1 × 10^−11 have a 2× margin. All match.
- Executed: 10,000 commits per trial across 5 years, `h` ∈ {1.787, 20, 365}, the incremental epoch up to 1,008 half-lives below `refTs`, sums in reversed and shuffled order. Worst relative ratio difference 1.444 × 10^−14, far inside 1 × 10^−11. The derivation holds at the seeds. Its general-`n` and `pow` premises are F5-14. Its crash rule is F5-6.
