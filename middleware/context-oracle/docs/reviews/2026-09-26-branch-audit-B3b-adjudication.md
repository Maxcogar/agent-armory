### E-7
**Ruling:** Both reach `replace`, and the shared core stands: the purge set is complete and in one transaction; chunks commit with their watermark; the handler's write groups are minimal; `mining_in_progress` is specified but not `status`-visible. Both auditors executed the same harness and got the same result, re-run here: with the architecture's event-path rule (100 ms `busy_timeout`, `BEGIN IMMEDIATE`, one immediate retry) against a conforming pass writing back-to-back 50 ms chunks with no gap, the handler's audit write failed on every run that overlapped the pass (1 of 15 succeeded; the second opinion's run shows the one success printed after the miner exited). So chunk length is not what bounds the handler's wait; the gap between chunks is, and `ec3b057` states none — the lock bound does not achieve what AD-26 says it achieves, and `OL-C3`'s deny stays off during a full pass. The two differ on the size of the fix. The first audit's "yield for at least the event path's full wait (~200 ms)" falls: it is not derived from anything (the ~200 ms is the handler's total patience, not the interval between its lock attempts) and it costs about 4 s of idling per second of writing at 50 ms chunks. The second opinion's derivation is right in substance and is restated exactly per coordinator fact (3): under a 100 ms `busy_timeout` the default busy handler attempts the lock at offsets 0, 1, 3, 8, 18, 33, 53, 78 and 100 ms (the ninth sleep of 25 ms is clipped to 22 ms by `if( prior + delay > tmout )`, and the tenth returns 0), so the longest interval between two attempts is 25 ms; a gap of at least 25 ms between a chunk's `COMMIT` and the next `BEGIN IMMEDIATE` therefore always contains an attempt, which acquires the free lock. The second opinion's sentence "sleeps at most 25 ms between polls within a 100 ms timeout" is true only with that qualifier — the 50 ms and 100 ms sleeps begin after 103 ms total, so the property does not hold for a longer timeout. Executed here: 0 ms gap → 1/15; 5 ms → 13/15 (the second opinion's 15/15 at 5 ms was luck, not a guarantee); 25 ms → 15/15; 50 ms → 15/15. Because 25 ms is exactly the 53→78 attempt spacing, the seed should carry a margin above it; the derived floor is 25 ms.
