### E-1
**Agree/Disagree:** Verdict: agree (`replace`). Reasoning: agree, with two corrections and one defect the first audit missed.

The exit-128 finding stands. git documents only 0 and 1 for `--is-ancestor` and treats every other non-zero status as an error, and 128 came back here both for a missing object and for a non-repository. The plan reads a code that also means "git could not run here" as "history was rewritten", and it answers with a purge of every history table. That is a data-destroying fallback on an ambiguous signal. The inherited items stand as the first audit states them: the missing inter-chunk yield (B3b E-7), the unsourced `lexicon.fix_keywords` seed (B3b E-14), the ROSE "support(A)" term (B3a E-7), and the 414 ms "event" that is only a projection (B3b E-22).

Correction 1, the horizon. The first audit confines this to the commit-count horizon. The time horizon has the same property. Both horizons are tested only against the commits in the pass's own `<range>`. An incremental range holds only new commits, so neither horizon excludes anything on an incremental pass. Pairs and `change_count` bumped years earlier are never aged out; only the landmine rebuild re-applies a time window. So the corpus is horizon-capped only at a full mine, for both horizons.

Correction 2, what the purge is keyed to. It is keyed to more than rewrites. The plan maps "watermark unreachable" (the architecture's words) to "`merge-base --is-ancestor <watermark> HEAD` exits 1". An ordinary branch switch produces exactly that exit. Leave a feature branch whose tip is the watermark, switch to a `main` that does not contain it, and git exits 1. The `SessionStart` path then sees `HEAD` differ from `index_head` and spawns `index`. The miner purges every history table, records `history_rewritten` for a history that was not rewritten, and runs a full chunked re-mine. That re-mine is the lock-holding pass batch 3 measured switching the OL-C3 deny off. It also sets `mining_in_progress`, which silences every history genre for the duration.

Given the aggregate storage model (no per-commit touched-file lists outside `labelled_touches`), re-mining after a branch switch may be unavoidable. It is still an engineering decision that has to be stated. The plan justifies the purge only with `git commit --amend`. It gives the purge no frequency bound, and its diagnostic name misreports the cause. A `replace` must either separate the two cases (rewritten versus moved to a non-descendant) with a truthful diagnostic and a stated cost, or state why they are treated alike.

### E-3
**Agree/Disagree:** Verdict: agree (`replace`). Reasoning: agree on the TypeScript label, the workspace inheritance (B3b E-15), the Python `src`-layout defect, and the parse-failure bound. One point in the reasoning is wrong, and it changes what the verdict must fix. The first audit calls the plan's `.js`→`.ts` substitution "the handbook's rule" and lists it among the parts to keep. The plan's order is the reverse of the handbook's. The plan tries "the written path if it exists" first, and the source `.ts` only after it, and the first existing file wins. TypeScript's extension substitution tries `.ts`, `.tsx` and `.d.ts` before `.js`, whatever specifier is written. Take a repository that commits both `util.ts` and a generated or shim `util.js`: the plan resolves `./util.js` to `util.js`, while the compiler resolves it to `util.ts`. The edge points at the wrong file, and Reuse, Orientation and the unresolved share all count it that way. The plan also never tries `.d.ts`. So the substitution cannot be kept as written. Its order must follow the handbook, TypeScript file first.

PyPA's guide backs the `src`-layout point: the layout moves the importable code into a subdirectory, and that code is importable only once installed. That is `sys.path`, not the repository root. The TypeScript label point is backed too: under `nodenext`, extensionless relative paths are rejected in `import` and allowed only in `require`.

One caution on the parse-failure point. The first audit leans on a later Step 15 review ("about 75 crashes corrupt the WASM runtime"). That is hindsight, outside the as-of-commit judgment the brief asks for. The point stands without it. A catch "whatever its class" that swaps frontends per file, with no stated fault class and no bound, is the catch-and-continue pattern the fail-fast rule governs.
**Evidence:**
- The plan's order: [[middleware/context-oracle/docs/plans/plan-phase-a.md@2331baf:L3416-L3420]] "specifiers (`./`, `../`): the written path if it exists; a `.js`/`.jsx`/ `.mjs`/`.cjs` specifier also tries its source `.ts`/`.tsx`/`.mts`/`.cts`; an extensionless one tries `.ts`, `.tsx`, `.js`, `.jsx`, then `/index.` + those; first existing file wins"
- The handbook's order: [[https://www.typescriptlang.org/docs/handbook/modules/reference.html]] "TypeScript will first try to find a TypeScript implementation file or type declaration file with the same name and analagous file extension" and [[https://www.typescriptlang.org/docs/handbook/modules/reference.html]] "Note that this behavior is independent of the actual module specifier written in the import."
- `nodenext` and extensionless imports: [[https://www.typescriptlang.org/docs/handbook/modules/reference.html]] "in --moduleResolution nodenext , directory modules and extensionless paths are only supported in require calls, not in import s"
- The Python rule: [[middleware/context-oracle/docs/plans/plan-phase-a.md@2331baf:L3430-L3434]] "an absolute dotted name resolves against the repository root (`a.b` → `a/b.py` or `a/b/__init__.py`) → `resolved` when it exists, otherwise `external` (Python has no alias mechanism in the language; an absolute name outside the repository is the standard library or an installed distribution)"
- PyPA: [[https://packaging.python.org/en/latest/discussions/src-layout-vs-flat-layout/]] "moving the code that is intended to be importable" and [[https://packaging.python.org/en/latest/discussions/src-layout-vs-flat-layout/]] "The src layout requires installation of the project to be able to run its code, and the flat layout does not."
- The catch-all: [[middleware/context-oracle/docs/plans/plan-phase-a.md@2331baf:L3370-L3375]] "A parse that throws — a `TypeError` from an unresolved scanner import, a `RuntimeError` from a trap — is caught whatever its class: the frontend discards that parser instance (one that threw is dead afterwards, executed), indexes the file through the generic frontend, and records `frontend_parse_failed`"
**Correct verdict:** replace — the first audit's changes, except that the `.js`→`.ts` substitution is not kept as written: it must try the TypeScript file (`.ts`/`.tsx`/`.d.ts`) before the written `.js`, as the handbook specifies.
