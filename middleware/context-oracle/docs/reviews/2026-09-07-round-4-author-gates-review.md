## 1. What changed in the process before this pass

The diagnosis (`docs/collapse-log.md`, 2026-09-07) was that the author's pre-review check reconciled identifiers while the reviewers walked the build in order and executed claims; every round-2 and round-3 regression lay between those two checks. The owner rejected a first fix (a plan-local gate script, a written rule, and an extra review pass) as either not a fix or not general. The fix that stands is in the expert-plan skill itself (`claude-plugins/expert-dev-tools/skills/expert-plan/`, version 0.4.2, synced to `.claude/skills/expert-plan/`), so it applies to every plan written under the skill:

- **Facts are declared once.** Every step opens with a `step-decl` block (files created/modified/deleted, names provided, tests, dependencies, elements covered); §5.1's file table, §2.3's coverage table, and §12's step→test table are generated from those declarations and regenerated by `derive-plan-sections.mjs`; the hand-kept §5.1 tree, the hand-kept §12.4 step table, and each step's hand-written Dependencies list — the sites of the round-2/3 count and inversion regressions — no longer exist as authored text.
- **Build order is checked from the declarations.** A step's text may backtick only artifacts that it, or a declared or transitive dependency, creates or provides; a dependency on a later step, a path two steps create, and a path under a created directory that no step declares are errors. Run on the round-3 text, this check reproduced every round-3 build-order finding (S1's guard/watchdog/`integrity-check`, the `tuning.ts` and `classify.ts` forward mentions) and two the round did not name (`tuning_seeds.ts` and `regret.ts` undeclared).
- **Executed evidence is executable.** Seventeen probes under `docs/plans/plan-phase-a.probes/` are the executions §11.4 rests on; `run-plan-probes.mjs` re-runs them and fails on drift, and `--check` fails a citation with no probe or a probe with no citation. T-3-3's schedule, the container image, the brand's reach, and the clause-level clear rule were each executed as a probe before the plan text was written.
- **Reviewer prescriptions were re-derived, not transcribed.** Each round-3 "required change" was read against its cited source before being written, and four were changed in the re-derivation: S-2's optional `deny_after_deferral` diagnostic was not added (a new fault code for a non-wrongful event the block already handles is padding); M-7's two options collapsed to "keep the pin, make its death visible" because the PATH-resolved alternative changes what probe 06 verified; M-2's rule attribution moved to the plan (D-plan-26) rather than to a new owner question; M-8's "strip the phrase or the clause" became the clause-level rule with an acknowledgement lexicon, because the phrase-only variant leaves "Sure"/"Ok" fragments that clear on the floor (executed, probe 16).
