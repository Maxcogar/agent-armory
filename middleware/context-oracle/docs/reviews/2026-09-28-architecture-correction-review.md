## Settlements of the four open items

### (a) R-20's symbol-name length bound — cannot be settled as a sourced constant

- What asked for it: [[middleware/context-oracle/docs/reviews/2026-09-26-step-15-build-review.md@HEAD:L300-L303]] "`SH_NAME` and tree-sitter identifiers accept a name as long as the file (up to the 1 MB cap). ASVS 5.0 V5 bounds input." and its number is an example only: [[middleware/context-oracle/docs/reviews/2026-09-26-step-15-build-review.md@HEAD:L302-L303]] "drop or truncate names over a fixed length (for example 256 characters) before storage."
- Storage is already bounded, by the ingestion cap: [[middleware/context-oracle/docs/architecture-phase-a.md@HEAD:L1791-L1792]] "files > 1 MB or > 20k lines are indexed path-only with a diagnostic."
- The only primary-source bound on what a name costs downstream is the harness's delivery cap: [[https://code.claude.com/docs/en/hooks.md]] "A hook's additionalContext, systemMessage, and initialUserMessage strings, and its plain stdout, are capped at 10,000 characters:" and [[https://code.claude.com/docs/en/hooks.md]] "Claude Code saves the output to a file in the session directory and replaces it with the file path and a preview of up to the first 2,000 characters." and [[https://code.claude.com/docs/en/hooks.md]] "Claude Code doesn't ask Claude to read the file, so keep anything Claude must always see within the cap."
- [[ran]] `grep -n -i '10,000 char\|capped at 10\|2,000 char' middleware/context-oracle/docs/architecture-phase-a.md middleware/context-oracle/docs/specs/spec-context-oracle.md` → no output (neither document handles the cap).
- Why no constant follows: the cap bounds a whole response, and a response carries every whisper that clears the bar at one event, with no volume term ([[middleware/context-oracle/docs/architecture-phase-a.md@HEAD:L2385-L2386]] "**No volume/count/budget term exists in the code path** (`OL-C1`; AC-3). Two candidates clearing the bar at one event are both delivered."). A per-name bound derived from it would be `(10,000 − template text) / (names in the response)`, and the number of names in a response is unbounded by design. No language standard supplies one either (ECMAScript, Java and Python identifiers have no maximum length). So a name bound is derivable only after the composer has a rule for meeting the 10,000-character cap, and if that rule has to drop whispers it is an OL-C1 question for Max Cogar (F-22).
- Settlement: R-20's bound stays unmade, with this reason written in AD-12; names are stored in full (bounded by the ingestion cap); the composer's cap rule is designed first (F-22), and the name bound, if still needed, is derived from it.

### (c) R-36's `miner.chunk_gap_ms` seed margin — derived from measurement

- The floor and the claim it rests on: [[middleware/context-oracle/docs/architecture-phase-a.md@HEAD:L3661-L3663]] "The longest interval between attempts within 100 ms is 25 ms (78 − 53), so a free window of at least 25 ms always contains one." and the deferral [[middleware/context-oracle/docs/architecture-phase-a.md@HEAD:L3627-L3629]] "whose floor 25 ms is derived and whose seed carries a margin above it, illustrative; its value is set with the other seeds in Step 12"
- What sets the real interval: SQLite's unix VFS sleeps with `nanosleep` ([[https://raw.githubusercontent.com/sqlite/sqlite/version-3.51.2/src/os_unix.c]] "static int unixSleep(sqlite3_vfs *NotUsed, int microseconds){" and [[https://raw.githubusercontent.com/sqlite/sqlite/version-3.51.2/src/os_unix.c]] "nanosleep(&sp, NULL);"), so the interval between the attempts at 53 and 78 ms is 25 ms plus that sleep's overshoot, which the scheduler decides.
- Measured, the overshoot of the busy handler's own 25 ms sleep inside `node:sqlite` (Node 22.22.2, the `HEAD` adapter's default open, a lock held by a second process): [[ran]] `$A/gap/measure.sh <spinners> 300 <label>` (each give-up of one busy schedule timed, then the same 300 under `strace -f -tt -T -e trace=clock_nanosleep,nanosleep`) → `idle spinners=0` / `sleep   25 ms: n=300 overshoot p50 0.163 p99 2.941 max 4.167 ms`; `spin3b spinners=3` / `sleep   25 ms: n=300 overshoot p50 0.179 p99 3.990 max 19.312 ms`; `spin8 spinners=8` / `sleep   25 ms: n=300 overshoot p50 0.122 p99 5.256 max 8.058 ms` (traced, so upper bounds). Untraced, the same sleep in C: [[ran]] `$A/gap/sleep25 2000` under 0, 3 and 8 CPU spinners on 4 cores → `spinners=0: n=2000 overshoot p50 0.191 p99 1.833 p999 7.648 max 34.313 ms` / `spinners=3: n=2000 overshoot p50 0.100 p99 2.599 p999 3.870 max 3.938 ms` / `spinners=8: n=2000 overshoot p50 0.095 p99 3.711 p999 9.312 max 12.852 ms`.
- The effect on a waiter, directly: a writer holding the lock 60 ms per transaction with gap `G`, against a one-try autocommit waiter (`busy_timeout` 100, no retry) through the `HEAD` adapter: [[ran]] `$A/gap/sweep.sh <spinners> 60 <G> <ms>` → 30 s runs, 3 spinners: `spinners=3 H=60 GAP=20 {"ok":273,"busy":93,"maxWaitMs":105}` / `spinners=3 H=60 GAP=25 {"ok":439,"busy":1,"maxWaitMs":102}` / `spinners=3 H=60 GAP=30 {"ok":444,"busy":0,"maxWaitMs":87}` / `spinners=3 H=60 GAP=35 {"ok":571,"busy":0,"maxWaitMs":89}`; 180 s runs, 3 spinners: `spinners=3 H=60 GAP=25 {"ok":2598,"busy":15,"maxWaitMs":129}` / `spinners=3 H=60 GAP=30 {"ok":2729,"busy":0,"maxWaitMs":153}`; 120 s runs, 8 spinners: `spinners=8 H=60 GAP=25 {"ok":1640,"busy":13,"maxWaitMs":107}` / `spinners=8 H=60 GAP=30 {"ok":1801,"busy":1,"maxWaitMs":119}`.
- Derivation. (1) A gap guarantees one attempt only if it is at least the longest real interval, 25 ms plus the 25 ms sleep's overshoot. (2) That overshoot has no upper bound on a general-purpose scheduler (34.3 ms once in 2,000 idle sleeps), so no finite margin guarantees capture; the margin is chosen to cover a stated percentile, and the rest is absorbed by what the architecture already has — the retry-once (the two tries together span about 200 ms, which always contains a full gap when a hold stays within `miner.chunk_ms` plus one write) and the recorded holds. (3) Cover the 99th percentile of the untraced overshoot under every measured load: max(1.833, 2.599, 3.711) = 3.711 ms, so the margin is at least 4 ms; 5 ms is the smallest margin measured directly, and it removed the one-try misses under 3 spinners (15 of 2,613 at 25 ms against 0 of 2,729 at 30 ms) and cut them fourteen-fold under 8 spinners on 4 cores (13 of 1,653 against 1 of 1,802). (4) Seed `miner.chunk_gap_ms` = **30 ms** (floor 25 + margin 5); `tune` keeps refusing a value below the 25 ms floor. (5) Cost, from the recorded benchmark: the 25 ms yield added 148.4 − 98.2 = 50.2 s, about 2,008 gaps of 25 ms; 5 ms more per gap adds about 10.0 s (158.4 s, +61 % over no yield, against +51 %).
- Settlement: made — not left for Step 12, because Step 12 has no more information than this measurement; Step 12 writes the seed and cites this derivation. AD-26's "always contains one" sentence gains the qualification in (1)–(2).

### (d) G-1's equality exception when `refTs` moves — settled: a root-cause design exists

- The cause, at `HEAD`: the term is capped at the pass's `refTs`, a quantity of the pass, not of the commit: [[middleware/context-oracle/ctxoracle/src/miner/cochange.ts@HEAD:L567-L568]] "ts capped at refTs (a commit cannot carry more recency than <head>). const w = 2 ** ((Math.min(c.ts, refTs) - epoch) / hS);"
- The store already holds everything the recompute needs: the raw author time [[middleware/context-oracle/ctxoracle/src/miner/cochange.ts@HEAD:L563-L563]] "commits.upsert({ hash: c.hash, ts: c.ts, entityCount: c.entityCount, excluded: c.excludeReason !== null, excludeReason: c.excludeReason });", the previous pass's `refTs` [[middleware/context-oracle/ctxoracle/src/miner/cochange.ts@HEAD:L629-L629]] "meta.set('ref_ts', String(refTs));", and, under G-1, each commit's term and touched files [[middleware/context-oracle/docs/architecture-phase-a.md@HEAD:L1930-L1932]] "then **recompute**, from `commit_touches` joined to `commits.weight`, every affected file's `change_count` and `change_weight`"
- The invariant the exception breaks is the one the reconcile rests on: [[middleware/context-oracle/docs/architecture-phase-a.md@HEAD:L2126-L2128]] "following at mining time would make a commit's contribution depend on a later rename commit, which breaks the order-independence the reconcile rests on"
- Design (root cause: make each stored term the function of the commit and the current `refTs` that a fresh mine computes):
  1. After `refTs` is validated (G-8) and before the evict step, let `R0` = the stored `schema_meta.ref_ts`. When `R0` exists and `R0 ≠ refTs`, the re-weight set is `W = {c ∈ S ∩ T : c.weight IS NOT NULL AND c.ts > min(R0, refTs)}` — exactly the commits whose `min(ts, ·)` differs between the two instants (for `ts ≤ min(R0, refTs)` both minima equal `ts`).
  2. For each `c ∈ W`, set `commits.weight = 2^((min(c.ts, refTs) − E)/h)`, then recompute every file and pair it touches from `commit_touches` joined to `commits.weight`, with the eviction's recompute, in chunked, yielded transactions (AD-26).
  3. `ref_ts` is written in the final transaction, as now. A crash before it leaves `R0` unchanged, so the next pass recomputes the same `W`; re-applying step 2 to an already re-weighted commit writes the same value, so the step is idempotent and needs no recorded range.
  4. Cost: `W` is the set of commits whose author time is later than a tip's committer time — the ones the capped-commit fault already counts; normally empty, and one query over at most `miner.horizon_commits` rows off the event path.
- With it, every term equals a fresh mine's at the same `refTs`, so AD-13's equality clause holds with no exception, in both directions of a `refTs` move (E-5). The exception sentence goes.
